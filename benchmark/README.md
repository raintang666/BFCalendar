- **两台手机都减少了首页收缩和拉伸时准备画面的耗时。** STK TL00 的首页收缩 UI P95 从 51.33 ms 降到 8.95 ms，中位数仍在约 4.5–4.8 ms，收益主要体现在偶发慢帧。日常月、周翻页的 UI P95 变化较小。
- **一加的采样整体更稳。** 超预算帧从 15/1783 降到 0/2365。首页拉伸时，准备画面和实际绘制都更快。默认样式拉伸的 UI P95 从 3.41 ms 升到 3.76 ms，这组仍没有采到超预算帧。
- **STK TL00 的拉伸仍受实际绘制耗时限制。** 首页拉伸准备画面的 P95 从 18.17 ms 降到 11.55 ms，实际绘制的 P95 从 17.48 ms 升到 19.98 ms，超过该机约 16.67 ms 的预算。12 个场景合计超预算采样比例从 25.5% 升到 26.6%。

各场景重复 3 次，合计比例按实际采到的帧统计。单个场景的采样较少时，几帧波动就能影响 P95。两台设备的刷新率和渲染后端不同，性能变化以各自的改前改后为准。 [STK TL00 改前](results/android10_canvas_migration_before.json) · [STK TL00 改后](results/android10_canvas_migration_after.json) · [一加改前](results/oneplus_plk110_canvas_migration_before.json) · [一加改后](results/oneplus_plk110_canvas_migration_after.json)

## 2026-11-17 交互优化记录

UI 开销明显降低；这台设备的 GPU/raster 慢帧仍然存在，部分场景的 raster P95 还有波动或上升，不能据此声称全程 60 FPS。首页 Widget 全屏拉伸的 UI P95 仍约 20ms。完整数据保留了这些限制，未以 UI 耗时下降替代最终帧率结论。

本次修复包括：静态头部、星期栏和内容构建复用；修复 Widget 日期缓存每帧失效；日历和列表在同一次布局中对齐；隔离日期网格重绘；首页单元格按宽度复用内容；内置画笔共用有容量上限且随字体更新失效的文本布局缓存；保留分页控制器并延迟到布局后复位；将农历预热签名计算移出滚动帧。公开构造参数、回调和样式构建入口保持兼容。
